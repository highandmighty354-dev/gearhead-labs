## Two harness defects found while gathering evidence (fix before judging any registry change)

- **H1 — invalid-state false failures.**
  - When the live page rejects an input, it shows a "Validation required" / "Invalid …" box. That box's label matches no registry output.
  - The harness reported "no matching live result" instead of checking that both sides agree the input is invalid.
  - Fix: when an output has no label match and the live page shows only non-numeric result boxes, the live state for that output is **invalid**, and the engine output must be `null`.
  - The check stays strict: a number from the engine while the live page shows invalid still fails.
  - Three calculators fail today *only* because of H1: `crawl_ratio_tire`, `ev_quarter_mile`, `winch_line_pull`. Their registries already carry the correct NaN guard.
- **H2 — validity-only live inputs were not probed.**
  - The unbound-live-input check only scaled extra inputs (×1.13). A live input that affects validity but not the value (e.g. `brake_bias` Static Front Weight %) slipped through.
  - Fix: also set each unbound live input to 0. If the validity of a registry output changes, the registry is missing that input.
  - This makes the check stricter.

**Why the 11 are not closable under the M1.2 rules:**
- `GH_ENGINE`'s input contract accepts numbers only. A string is recorded as unknown with `NON_NUMERIC_INPUT`, which is deliberate: never coerce.
- A text selector can enter the engine only by either:
  - **(a)** extending the engine input contract to accept named options declared in the registry. That is formula-free, but it is a change to the shared engine, which M1.2 forbids.
  - **(b)** inventing numeric codes (1 = head, −1 = tail). That is a new convention, which M1.2 forbids.
- Both need an owner decision. **Recommendation: (a).** Each registry entry would declare its allowed option strings, the engine would validate against that list, and anything else would be unknown. The live select values (`'head'`, `'mi'`, …) become the canonical option ids, with no numeric codes invented.
