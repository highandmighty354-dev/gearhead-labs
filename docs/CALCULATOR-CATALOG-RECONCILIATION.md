# Calculator catalog reconciliation: 606 public calculators vs 583 catalog rows

**Status:** explained; **not** a production defect. Must be acted on before the trusted calculation-saving service is built.
**Checked:** 2026-10-06 against production `jmztpjudwzjvrcdtjynd` (read-only) and F1.12.4 / frozen F1.12.3 loaded in Chromium.

## The numbers

| Source | Count | What it contains |
|---|---|---|
| Page (`CALCS`, excluding `dashboard` and the Premium engineering layer) | **606** | every public calculator card; identical id set in F1.12.3 and F1.12.4 |
| Engine formula registries (`GH_E1_FORMULAS`, `GH_E101_FORMULAS`, `GH_LEGACY_FORMULAS`, `GH_BACKFILL_FORMULAS`) | **577** | calculators with a fingerprintable formula |
| `public.calculators` (production) | **583** | the 577 registry calculators (each its own canonical id, each with a `formula_versions` row) **+ 6 legacy alias ids** |
| `public.formula_versions` (production) | **577** | one per registry calculator |

**606 = 577 + 29.** **583 = 577 + 6.**

## Why they differ

The catalog in `0005_reference_seed.sql` was generated by `data-foundation/tools/export-engine-catalog.js` (tag `VALUE-FOUNDATION-1.0.0`) **from the formula registries only**, by design: a `calculation_records` row must reference a `(calculator, formula_version)` fingerprint, and only registry calculators have one.

- **6 catalog-only ids** are legacy aliases (`calculator_id <> canonical_id`). None is a public card; each points to a registry calculator:
  `airflow_from_ve → engine_airflow`, `carb_cfm → carb_sizing`, `fraction_to_decimal → fraction_decimal`,
  `sae_fraction_to_mm → inch_fraction_to_mm`, `valve_curtain_area → curtain_area`, `volumetric_efficiency → volumetric_eff`.
- **29 page-only calculators** have **no entry in any formula registry** (verified in the live page: 0 of 29 in a registry; all 29 render). They are simulators, multi-event cam/valve tools, lookup charts and diagnostic helpers:

## Production impact today: none

- The Premium frontend never reads `public.calculators` and never writes `calculation_records` or `value_records` (production grants no client INSERT on either).
- Saved calculations cannot be created from the browser (`savedCalculations.canCreate = false`; no INSERT path in the adapter).
- All 606 Free calculators run entirely in the page and do not touch the database.

## Required before the calculation-saving service

For each of the 29, decide one of:

1. **Saveable:** give it a registry formula in a new engine build, then add its `calculators` + `formula_versions` rows in a new, reviewed migration (never by editing the frozen 0005), or
2. **Not saveable:** explicitly exclude it (simulators, reference charts and diagnostics are likely candidates), and have the service refuse it with a clear message.

The service must also resolve alias ids to their canonical id before writing (the database enforces `canonical_id` = the catalog's canonical id via `df_calculation_validate`).

**Canonical catalog:** every public calculator, its save status (eligible / needs_decision), the aliases and the Premium-only tools are now listed in `catalog/gearhead-catalog.json`, explained in [PREMIUM-CATALOG.md](PREMIUM-CATALOG.md).
